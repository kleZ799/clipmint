Two fixes, and the version on every screen.

## The window no longer opens unstyled

Now and then ClipMint opened as plain black text on white, with the menu
lying on top of the page and nothing laid out. The page had arrived but its
look hadn't, and the window had no way to fetch it again. The look now comes
inside the page itself, so it can't go missing on its own. If part of the app
ever fails to load, the window reloads itself.

If it happened to you, closing and reopening the app fixed it. After this
update it shouldn't happen at all.

## The prompt box reads "hooks" correctly

Typing "hooks that ask a question" switched on **Start each clip with its own
loudest moment**, because the word "hooks" was taken as that setting. It now
means what you meant: the kind of moment to look for. That setting is decided
only by its checkbox. The reply under the box also says the right number of
clips when you don't name one: "I'll find 10 clips with hooks that ask a
question", not "a clip".

## The version is in the corner

Every screen now shows which build you're on in the bottom-right corner, like
**ClipMint v1.26.1 · windows**. It stays there over pop-ups and the player, so
a screenshot of a problem says which version it came from without anyone
having to ask.

---
**ClipMint.exe**: about 224 MB, Windows, self-contained. Unsigned, so
SmartScreen will warn: **More info → Run anyway**.

**ClipMint-linux-x86_64**: about 280 MB, x86-64, self-contained, glibc 2.35 or
newer. `chmod +x` it and run it. **Still untested on a desktop distribution.**
Every published build is started by the release workflow and asked for its
interface before the release exists, but nobody has yet made a Short with it
on Fedora or Ubuntu. Take `ClipMint-linux-README.txt` too.

**ClipMint-macOS-arm64.zip**: about 167 MB, Apple Silicon only. **Still a beta,
and still has never been run on a Mac.** I don't own one, so it is built and
checked by GitHub's macOS runners and published without a person opening it.
Uploading to YouTube has only been tested on Windows. If it doesn't start, or
signing in doesn't behave as described, that is a bug here:
`~/Movies/ClipMint/app.log` and
[an issue](https://github.com/kleZ799/clipmint/issues/new) are how it gets
fixed.

Also published, for installs from before the rename only: `StreamToShorts.exe`,
`StreamToShorts-linux-x86_64` and `StreamToShorts-macOS-arm64.zip`, the same
three files under their old names. A fresh download wants the ClipMint ones.

On v1.5.0 or later on Windows, or on any Linux build? The app will offer this
to you.
