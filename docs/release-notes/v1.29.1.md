One fix, from a feedback-form answer: asking for several clips with a length
in timestamps no longer makes one clip of the video's opening.

## "5 clips of 0:30-1:00" makes five clips

Asking for *5 clips of 0:30-1:00* meant five clips half a minute to a minute
long. The app read the timestamps as an exact cut instead, and an exact cut
skips the AI choosing entirely, so the run made one clip, from 0:30 to 1:00:
the opening of the video. *5 clips, 30s - 60s, cut the boring parts* did the
same, because any "cut" in a request turned clip lengths off.

Now:

- **A count beside one span is a length.** *5 clips of 0:30-1:00* makes five
  clips 30 to 60 seconds long. Two or more spans, or one clip with one span,
  are still exact cuts, and so is a span after "from": *2 clips from 1:00 to
  1:30*.
- **"cut" means an exact cut only right before a time.** *cut 14:45 to 15:30*
  still cuts exactly that. *cut the boring parts* is just part of what you
  want, and the length beside it is kept.
- **Length ranges read the way you'd write them.** *30s-60s* was read as 30
  seconds flat; now it's 30 to 60. *30sec-1min* and *1-2 minutes* work too.

The preview under the prompt shows which one it read: exact cuts get an
**Exact cuts — no AI ranking** box.

**ClipMint.exe**: about 224 MB, Windows, self-contained. Unsigned, so
SmartScreen will warn: **More info → Run anyway**.

**ClipMint-linux-x86_64**: about 280 MB, x86-64, self-contained, glibc 2.35 or
newer. `chmod +x` it and run it. **Still untested on a desktop distribution.**
Every published build is started by the release workflow and asked for its
interface before the release exists, but nobody has yet made a Short with it
on Fedora or Ubuntu. Take `ClipMint-linux-README.txt` too.

**ClipMint-macOS-arm64.zip**: about 167 MB, Apple Silicon only. **Still a beta,
and still has never been run on a Mac.** I don't own one, so it is built and
checked by GitHub's macOS runners and published without a person opening it.
Uploading to YouTube has only been tested on Windows. If it doesn't start, or
signing in doesn't behave as described, that is a bug here:
`~/Movies/ClipMint/app.log` and
[an issue](https://github.com/kleZ799/clipmint/issues/new/choose) are how it gets
fixed.

`StreamToShorts-linux-x86_64` and `StreamToShorts-macOS-arm64.zip`, the same
three files under their old names. A fresh download wants the ClipMint ones.
