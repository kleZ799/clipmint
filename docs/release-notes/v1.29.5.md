Seven fixes and a tidier look. Nothing new to learn.

## It looks the way it was meant to

Most of the app's text was being drawn in the wrong size and typeface. A
mistake in the stylesheet made the browser ignore 43 of its rules, so buttons
fell back to a default font, headings came out too big and too bold, and the
step numbers sat off-centre in their circles. That's fixed, and it is the
change you'll notice first: calmer headings, and buttons that fit their labels.

Also tidied:

- The search bar is one clean pill. It had a second boxed field drawn inside it.
- In the light theme, the YouTube icon was a solid black block. It's an icon again.
- In the player, **Download** no longer spills out of its button.
- The **Kind of video** choices wrap onto a second line; the last one used to be cut off.
- The number box in Settings matches the other fields.

## Fixes

- **A caption fix that fails now says why.** The error from **Burn in again**
  was being written into Settings, out of sight, so the spinner stopped and
  nothing else happened.
- **Progress no longer freezes after your PC sleeps.** If the connection
  dropped mid-run, the page stopped listening while the render carried on
  behind it. It picks the run back up now.
- **Going back to the latest release works.** If you're on a build newer than
  the latest release, the app offers a way back. The button was there; pressing
  it did nothing.
- **Settings had a blank button** under Model when only one provider was set
  up. Gone.
- **A run that can't start no longer leaves a "Queued 0%" panel** sitting under
  the error.
- **Esc answers the question in front of you.** On "Delete this clip?" it used
  to close the player behind the question and leave the question up.
- **Upload all** said **Close** where it should say **Cancel** after one
  finished batch.

**ClipMint.exe**: about 224 MB, Windows, self-contained. Unsigned, so
SmartScreen will warn: **More info → Run anyway**.

**ClipMint-linux-x86_64**: about 280 MB, x86-64, self-contained, glibc 2.35 or
newer. `chmod +x` it and run it. **Still untested on a desktop distribution.**
Every published build is started by the release workflow and asked for its
interface before the release exists, but nobody has yet made a Short with it
on Fedora or Ubuntu. Take `ClipMint-linux-README.txt` too.

**ClipMint-macOS-arm64.zip**: about 167 MB, Apple Silicon only. **Still a beta,
and still has never been run on a Mac.** I don't own one, so it is built and
checked by GitHub's macOS runners and published without a person opening it.
Uploading to YouTube has only been tested on Windows. If it doesn't start, or
signing in doesn't behave as described, that is a bug here:
`~/Movies/ClipMint/app.log` and
[an issue](https://github.com/kleZ799/clipmint/issues/new/choose) are how it gets
fixed.

Also published, for installs from before the rename only: `StreamToShorts.exe`,
`StreamToShorts-linux-x86_64` and `StreamToShorts-macOS-arm64.zip`, the same
three files under their old names. A fresh download wants the ClipMint ones.
