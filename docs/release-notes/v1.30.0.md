Claude joins the AI providers, and the app understands "cámara arriba".
Both came from one piece of feedback, written in Spanish
([#17](https://github.com/kleZ799/clipmint/issues/17)).

## Claude, if you would rather rank with it

Under **Settings → Model** there is a fifth provider: **Claude**, through
Anthropic's own API. Paste a key from
[platform.claude.com](https://platform.claude.com/settings/keys) and pick a
model.

Know one thing before you do: **Claude has no free tier.** Every request is
billed to your Anthropic account, which is why the model list shows prices
where Gemini's shows a daily allowance. Gemini, Groq and OpenRouter are still
free and still the default; nothing changes unless you choose this.

- It reads frames as well as text, so titles written from what is on screen
  work on it.
- If you have other keys saved, it sits last in the fallback order, after the
  free ones and after OpenAI. A run never moves onto it while a free provider
  can still answer.
- If Claude declines a request, Anthropic is asked to answer it with another
  of its models before the app gives up on it.

This is new and I could only test it against a stand-in server, not a paid
key. If a real key misbehaves, [tell me](https://github.com/kleZ799/clipmint/issues/new/choose).

## "Cámara arriba" works without the model

You can write the **What to make** box in any language, and the AI reads it.
But the AI is not always there: the live preview never asks it, and a spent
quota takes it away. What was left then only knew English. Ask for the camera
on top in Spanish on a day like that and the request was dropped, and if the
app had taken your stream for a podcast you got a clip framed on your face
with no camera panel at all.

Now these are understood directly, in English, Spanish, Portuguese, French,
German, Russian, Japanese and Hindi:

- **camera on top**: "cámara arriba", "câmera em cima", "caméra en haut", "Kamera oben"
- **no camera**: "sin cámara", "solo el juego", "sans caméra", "ohne Kamera"
- **follow my face**: "sigue mi cara", "suis mon visage"
- **it's a stream**: "mis directos", "ao vivo", "en direct"

English had the same gap one word along: "webcam on top" worked, "camera on
top" did not. It does now.

## When no webcam was found, the app says so

The camera-on-top layout needs to find your webcam in the picture. When it
cannot, the clip is the game on its own, and until now the only place that was
written down was the log. Open **Frame** on a clip like that and it tells you,
with what to type to point the search at the right corner.

## Smart App Control

Some Windows 11 PCs now block the app outright, with no **Run anyway**
([#19](https://github.com/kleZ799/clipmint/issues/19)). That is Smart App Control, it blocks every
unsigned program, and Windows gives no way to allow one. This release does not
fix that: it needs a code-signing certificate, which I am working on getting.
The README now has a section on it, with two ways to run ClipMint in the
meantime.

**ClipMint.exe**: about 226 MB, Windows, self-contained. Unsigned, so
SmartScreen will warn: **More info → Run anyway**. Smart App Control, if it
is on, will not offer that; see the README.

**ClipMint-linux-x86_64**: about 282 MB, x86-64, self-contained, glibc 2.35 or
newer. `chmod +x` it and run it. **Still untested on a desktop distribution.**
Every published build is started by the release workflow and asked for its
interface before the release exists, but nobody has yet made a Short with it
on Fedora or Ubuntu. Take `ClipMint-linux-README.txt` too.

**ClipMint-macOS-arm64.zip**: about 169 MB, Apple Silicon only. **Still a beta,
and still has never been run on a Mac.** I don't own one, so it is built and
checked by GitHub's macOS runners and published without a person opening it.
Uploading to YouTube has only been tested on Windows. If it doesn't start, or
signing in doesn't behave as described, that is a bug here:
`~/Movies/ClipMint/app.log` and
[an issue](https://github.com/kleZ799/clipmint/issues/new/choose) are how it gets
fixed.

Also published, for installs from before the rename only: `StreamToShorts.exe`,
`StreamToShorts-linux-x86_64` and `StreamToShorts-macOS-arm64.zip`, the same
three files under their old names. A fresh download wants the ClipMint ones.
