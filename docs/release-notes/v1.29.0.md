The first four answers to the feedback form came in, and this release is all of
them. Thank you to everyone who wrote. Every change below is something one of
you asked for or ran into.

## Fixed

- **The webcam is found in any corner.** It was only ever looked for bottom-left
  unless your prompt said otherwise, so a webcam anywhere else came out as a
  plain centre crop. Now all four corners are searched, and the gameplay below
  is moved away from whichever side it was found on.
- **The cold open no longer looks like a glitch.** The second or so of a clip's
  peak played at the start, then hard-cut back to the beginning, which read as
  the video skipping. It now runs 2.5 seconds and hands over to the clip
  through a quick white flash, so it reads as a preview put there on purpose.
- **"No webcam" is understood however you say it.** "no web cam", "no
  facecam", "I don't have a webcam", "without my camera" and "camera off" all
  mean a plain gameplay crop now. Before, some of them slipped through, and the
  app kept searching every clip for a webcam that wasn't there.
- **A Groq key alone counts as set up.** Someone on Groq only was shown the
  first-run setup again on every start.

## New

- **Channel profiles.** Run more than one channel? Settings, **Channel
  profile**: each profile has its own YouTube sign-in, logo and logo corner,
  views data and edit choices. Switch, and uploads go to that channel. Your API
  keys and your clips are shared. Everything you had set up before is the
  **Main** profile, unchanged.
- **OpenRouter.** A fourth provider: one key in front of models from every lab.
  It defaults to OpenRouter's free router, so it costs nothing, and takes any
  model ID from openrouter.ai/models. It also joins the fallback chain, after
  Groq.
- **Spare Gemini keys.** Settings, Model: paste more Gemini keys, one per line.
  When one key's free day runs out, the run carries on with the next.
- **A title across the top.** A new checkbox under the edit, or words like
  "title at the top" or "title card" in your prompt, keeps the clip's title on
  screen for the whole clip. It works with captions off too.
- **Sports and fights.** A new kind of video, with its own rules for what a
  good moment is: the knockout, the goal, the buzzer-beater, on screen. Saying
  UFC, boxing, football, NBA or another sport in your prompt picks it.
- **Up to 30 clips a run.** Ten is still the default. Ask for "25 clips" and
  you get 25.
- **Stop, and Delete run.** Stop ends a run now; what it made so far is kept,
  so you can carry on later. **Delete** (on the "didn't finish" bar, and on
  every run in Your clips) removes the run's clips, its folder and the video it
  downloaded. A video you picked from your own files is never touched.

---
**ClipMint.exe**: about 224 MB, Windows, self-contained. Unsigned, so
SmartScreen will warn: **More info → Run anyway**.

**ClipMint-linux-x86_64**: about 280 MB, x86-64, self-contained, glibc 2.35 or
newer. `chmod +x` it and run it. **Still untested on a desktop distribution.**
Every published build is started by the release workflow and asked for its
interface before the release exists, but nobody has yet made a Short with it
on Fedora or Ubuntu. Take `ClipMint-linux-README.txt` too.

**ClipMint-macOS-arm64.zip**: about 167 MB, Apple Silicon only. **Still a beta,
and still has never been run on a Mac.** I don't own one, so it is built and
checked by GitHub's macOS runners and published without a person opening it.
Uploading to YouTube has only been tested on Windows. If it doesn't start, or
signing in doesn't behave as described, that is a bug here:
`~/Movies/ClipMint/app.log` and
[an issue](https://github.com/kleZ799/clipmint/issues/new/choose) are how it gets
fixed.

Also published, for installs from before the rename only: `StreamToShorts.exe`,
`StreamToShorts-linux-x86_64` and `StreamToShorts-macOS-arm64.zip`, the same
three files under their old names. A fresh download wants the ClipMint ones.
