YouTube's "confirm you're not a bot" no longer ends a download, and a run you
carry on stops paying for work it already did.

## When YouTube asks if you're a bot

Sometimes a download stopped at 0% with *"Sign in to confirm you're not a
bot"* — more often on a VPN, a shared connection, or after a lot of downloads.
It was never a broken link, but it ended the run all the same.

Now ClipMint asks again, differently. YouTube refuses its TV app, its phone apps
and its embedded player separately from the website, so the app tries each of
those first. That alone usually gets through, and there is nothing to set up.
Once one works, the rest of the run goes straight to it.

Only if none of them work does it use the YouTube sign-in from a browser on
your computer — which is what YouTube was asking for in the first place.

## Settings → YouTube sign-in

For when the gate keeps coming back, there's a new section in Settings:

- **Work it out** — the default. Uses any browser that's signed in to YouTube,
  lists what it found, and says in plain words why a browser can't be used.
- **Cookies from a browser** — pick one. It's checked before it's saved.
  - On **Windows**, use **Firefox**. Chrome and Edge lock their cookies so no
    other program can read them, and the app will tell you so rather than fail.
  - On a **Mac**, Chrome works; Safari needs ClipMint allowed under *System
    Settings → Privacy & Security → Full Disk Access*.
- **A cookies.txt file** — export one with a browser extension and point at it.
  It's checked too: an empty file, the wrong site, or an expired export is
  caught here instead of twenty minutes into a run.
- **Never use cookies.**

**Or skip Settings altogether:** drop the exported `cookies.txt` into
`%APPDATA%\ClipMint\` (on a Mac `~/Library/Application Support/ClipMint/`, on
Linux `~/.config/ClipMint/`) or into your clips folder, and it's picked up on
its own. The app only ever works from a copy — the download tool rewrites the
file it's given, and it was measured stripping the sign-in out of an export.
Yours stays exactly as you saved it.

Cookies never leave your computer; they go to YouTube, where they came from.
YouTube does see which account the downloads belong to, so if that matters,
sign a spare account in to one browser and use that one.

## Carrying on a run keeps the ranking

Resuming a long video was meant to skip everything already done. It skipped
the download and the transcript, and then asked the AI about every part of the
video again — all fifteen chunks of a four-hour stream, every time.

The cause was a few seconds. A transcript read back from disk reports the
video's length slightly differently from a fresh one, and that was enough to
make the saved ranking look like it belonged to a different video. It's
compared to the minute now, so a resumed run picks up the chunks it already
paid for.

## A better copy that won't download no longer loses the one you have

Choosing **best** quality with a lower-quality copy already downloaded makes the
app try for a better one. When YouTube wouldn't serve it, the whole run failed —
taking a finished 10 GB download, its transcript and its ranked moments with it.

Now it carries on with the copy you have. Everything made from that file is
still good, because it's the same file.

## Smaller things

- A settings field that was meant to be hidden stayed on screen — the Gemini
  model picker showed even for providers with no models to pick.
- The README now says how long a run takes: roughly, double the video, double
  the wait, with measured figures for each stage.

---

**ClipMint.exe** — about 220 MB, Windows, self-contained. Unsigned, so
SmartScreen will warn: **More info → Run anyway**.

**ClipMint-linux-x86_64** — about 278 MB, x86-64, self-contained, glibc
2.35 or newer. `chmod +x` it and run it. **Still untested on a desktop
distribution** — every published build is started by the release workflow and
asked for its interface before the release exists, but nobody has yet sat at
Fedora and made a Short with it. Take `ClipMint-linux-README.txt` too.

**ClipMint-macOS-arm64.zip** — about 165 MB, Apple Silicon only. **Still
a beta, and still has never been run on a Mac** — I do not own one, so it is
built and checked by GitHub's macOS runners and published without a human
opening it. That includes the new Safari and Full Disk Access handling, which
has only been checked by tests. If it does not start, or signing in doesn't
behave as described, that is a bug here: `~/Movies/ClipMint/app.log` and
[an issue](https://github.com/kleZ799/clipmint/issues/new) are how it
gets fixed.

Also published, for installs from before the rename only: `StreamToShorts.exe`,
`StreamToShorts-linux-x86_64` and `StreamToShorts-macOS-arm64.zip` — the same
three files under their old names. A fresh download wants the ClipMint ones.

On v1.5.0 or later on Windows, or on any Linux build? The app will offer this
to you.
