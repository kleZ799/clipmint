Very long videos now go through.

## "Unable to allocate 17.3 GiB"

A 32-hour stream failed at **Transcribing** with `ArrayMemoryError`, and then
failed the same way on every retry. The speech-to-text step prepared the audio
for the whole video in one piece. That takes about half a gigabyte per hour, so
a day-long stream needed more memory than most PCs have.

Now anything over 45 minutes is transcribed **half an hour at a time**. Memory
stays the same however long the video is: about 1.6 GB, measured on that
32-hour stream.

## A crash no longer throws away hours of transcribing

Each half hour is saved as soon as it's done. If the app closes, crashes or is
stopped partway through a long video, **Resume** carries on from the next half
hour instead of starting the transcript again.
